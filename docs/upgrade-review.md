# v0.2升级说明

## 用户得到的变化

预算与门店确定后，AI仍负责查当前菜单、详情和优惠，并准备最多三份完整餐单。新增批量入口把后半段接起来：请求核价 → 提取官方整单总额 → 检查偏好 → 比较预算 → 生成结果表。

用户现在可以明确要求最低份数、可替代餐品组和排除项。未满足数量、报价过期或餐单与请求不一致时，脚本不会把该方案列为推荐。全部超预算时给出最接近的方案和差额；第一次核价失败后，后续候选不再请求。

安装和展示新增了 Windows用户级安装脚本、快速开始、可本地检查的模拟计划，以及由初版真实核价摘要制作的历史效果预览。

## 验证证据

- `python -m unittest discover -s tests -v`：22项离线用例通过，覆盖金额单位、最低数量、排除偏好、替代组、时效、请求绑定、异常响应和停止行为。
- 模拟计划 `--check-plan`通过，不联网、不加载认证。
- 原模拟报价可以继续比较，输出¥23.00、¥28.50和超预算¥32.50，均标明模拟。
- 使用本机此前保存的三份真实响应离线回放，新入口得到¥14.90、¥22.90、¥26.90和对应预算余量；不更改原有验证日期，不发出新请求。
- 安装脚本通过PowerShell语法解析；效果图通过SVG XML检查；差异格式检查通过。

## 仍有明确范围的部分

新入口未重新进行真实服务联调；此次真实价格依据仍是初版2026年10月11日的运行记录。带券分支还没有新的真实账户案例。安装脚本未实际安装，效果预览未做渲染视觉验收。

候选挑选、菜单归类和优惠条件确认仍由读取实际 MCP结果的 AI完成。脚本不是全菜单最低价搜索器；每个套餐父项数量暂限1，独立单品可多份。不增加自动领券、下单、支付、外送或账户消费分析。

## 发布范围

更新原项目的代码与说明即可，不需要新建仓库或重新报名。报名 Issue保持原地址，参赛声明保持原文。新增脚本的原始响应只写入 `private/`，公开示例均无账户凭证。
