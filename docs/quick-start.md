# 从安装到第一份餐单

## 先看效果（不用连 MCP）

下载仓库后双击 `docs/preview.html`，不需要 Token、不联网。里面是 2026 年 10 月 11 日深圳南科大餐厅的三份真实历史餐单（¥14.90 / ¥22.90 / ¥26.90，含换无糖可乐后重新核价的 ¥22.90）：可以拖预算滑块看哪些餐单在预算内、剩多少钱、没有预算内方案时最接近的那份超了多少，也可以复制当前比较结果。

它只在这些**已经核过价的历史方案**之间筛选和排序，不会算出新价格；页面里的金额是历史快照，当前购买要重新查询与核价。在 GitHub 页面上直接点开只会看到源码，请先下载。

## WorkBuddy 已配好麦当劳 MCP

1. 在仓库页面点 **Code → Download ZIP**，解压。
2. 打开解压后的仓库文件夹，在地址栏输入 `powershell` 并回车。
3. 输入 `./install.ps1`。如果系统策略阻止运行，可以直接让 WorkBuddy复制 `skills/mcd-budget-meal` 到自己的用户技能目录，无需修改全局执行策略。
4. 新开 WorkBuddy会话，发送：

```text
使用麦麦预算餐技能。一个人，现在到店取餐，预算30元，想吃一个汉堡和一杯饮料。
先让我选门店。使用我的麦当劳 MCP查菜单、可用券和套餐详情。
比较最多三份真实核价的餐单，不下单。
```

5. 告诉它门店，或者提供用于查附近门店的位置，然后选一家。
6. 查看餐单表：餐品与份数、整单应付、剩余预算、优惠条件、核价时间。

已知的 WorkBuddy核价数组校验问题有项目直连路径，不需要重复删除连接器或改 Token。AI应按技能的兼容说明完成操作。批量入口要求本机 Python 3.10及以上；如果没有 Python，应说明无法使用脚本，不能把菜单价当核价结果。

## 其他 MCP 客户端

连接自己的麦当劳 MCP后导入完整技能目录。没有技能导入功能时，打开仓库目录，让 AI读取 `skills/mcd-budget-meal/SKILL.md`。客户端本身应支持远程 MCP；执行脚本还需要本机 Python。

## 还没配置麦当劳 MCP

打开 https://open.mcd.cn/mcp ，登录自己的账户、激活 Token，按官方接入指南配置 `https://mcp.mcd.cn` 的 Streamable HTTP连接器。Token仅填在自己的私有配置中。项目不提供公共 Token或替别人代理账户的服务。

## 常见情况

| 情况 | 应怎么处理 |
|---|---|
| 没有可用券 | 正常比较不带券的餐单，不要求领券 |
| 没有预算内方案 | 显示最接近的有效方案与超出金额，由你决定是否调整 |
| 不要某种饮料 | 换成门店真实可替代项，重新核价整个餐单 |
| 核价失败或限流 | 本轮停止后续调用，保留成功结果与失败原因 |
| 只想先看效果 | 下载后双击 `docs/preview.html`（免Token、历史快照），或看README的历史核价快照 |
| 换了门店或取餐条件 | 重新查询和核价，不沿用旧报价 |

## 怎样知道结果来自本次核价

结果要有门店、实际餐品、取餐方式、核价时间和官方返回引用。批量入口将实际请求与原始返回保存在用户指定的 `private/`子目录，并自动转换整单应付总额；该入口尚未重新做过真实 MCP 联调，2026年10月11日那次真实核价是初版单工具直连路径完成的。公开图示与 `docs/preview.html` 都是2026年10月11日的历史快照（公开依据只到当天 16:17–16:20 北京时间这一段），重跑价格可能变化。
